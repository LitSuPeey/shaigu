# 筛股——多功能选股工作台

把以下三个 A 股量化选股项目合并到了一个网页里：

| 来源              | 模块                                           |
| --------------- | -------------------------------------------- |
| `Sequoia-X`     | 6 大经典策略（海龟 / 均线放量 / 高旗形 / 涨停洗盘 / 上升跌停 / RPS） |
| 筛票demo          | 13 条件筛选 + 蚂蚁呀欸四层扫描                           |
| `scrensto（未发布）` | 形态打分（底部 / 顶部）+ 相似股查找                         |

## 功能模块

- **策略选股**：6 个经典策略，可单跑或一起跑，可自定义参数（K 线窗口、量比阈值、突破幅度、RPS 阈值 等）
- **条件筛选**：13 条财务/行情/资金面条件，AND 取交集，按 PE-TTM 升序；条件卡片整卡点击即可勾选
- **形态打分**：60% 形态相似 + 40% 趋势结构，自带 40 个底部+顶部样本池。面板内有 **🪄 经典形态 / ⚡ 短线快拍** 两个子页签。
  - **⚡ 短线快拍**：按 4 类短线机会筛选，可多选，各自 0~100 分（总分 = 命中模式里的**融合分** = 0.78×最高 + 0.22×次高）：**🔄 周期震荡**（短周期内振幅明显、顶底交替、节奏有持续性，用 ZigZag + **顶底价格水平性** + **振幅可比性** + **通道惩罚**量化）、**🚀 即将大涨**（缩量 + 位置低 + 波动收缩 + 年线未破 + **临界触发**，看 1~2 天）、**💪 反弹动能**（V 型回踩后收在区间上沿，右侧可即时买入，带**动能衰减闸门**）、**🪃 即将反弹**（回踩缩量 + 贴着支撑 + 止跌信号 + **临界触发**，左侧看 1~2 天）。
  - **「状态 × 时机」两层结构（v2 核心）**：4 类需求里 b / d 都明确写着「**1~2 天内**」，但 v1 的判据全是**存量状态**（缩量、低位、波动收缩）—— 这些条件可能今天满足、明天满足、半年后还满足，筛出来的是「随时可能启动但不知道哪天」的池子。R1 报告自己的回测也证明：**S1 触发当日买入 10 日胜率仅 41.2%，等确认信号（放量 + 收阳 + 站上 MA5）后买入胜率显著提升**。v2 因此新增 `_trigger()` **临界触发**维度（5 个子信号：放量确认 / 站上短均 / 首次异动 / 波动由缩转扩 / 贴压力位且有向上动能），合成方式为**乘法**而非线性加权：
    `最终分 = 状态分 × (0.80 + 0.35 × 触发分/100)`
    即**触发为 0 时打八折**（"值得关注，但不是今天"）、**触发满分时加价 15%**（"状态与时机同时到位"）。线性加权（v1 的初版做法）会把 80 分的好状态直接拉到 50 分，把「爆发前夜但当天还没确认」的真机会一票否决 —— 锚点校验里 300454 与 300672 就是这样被误杀的。
  - **v2 修掉的三个真实缺陷**：① **`date.today()` 未来函数**（判次新股用了系统当天日期，回测历史时点会把「当时是次新」的票放进来）→ 改用数据自身的日期；② **`min_vol20=0.30` 硬门槛误杀真机会**（300475 在 2025-08-01 因此被判「波动率不足」剔除，而它此后 60 日 **+330.5%**）→ 默认关闭，改为在模式内以**软得分**评估弹性；③ **`_mode_rebound` 会高分选中「反弹尾声」**（模板中心本身是「已反弹 40%+ 且创区间新高」的追高形态，且完全没有度量「持续性」）→ 新增 `_momentum_persist()`（末段/前段动能衰减比、量价配合、连涨根数上限、上影压制），并对尾声形态施加乘性折扣。
  - 方法论取自「短周期大涨股量化识别」与「形态匹配」两份研究报告并做批判性修正：位置 / 量能 / 带宽等门槛**一律换成全市场横截面分位数**（研究样本仅 7 只 40 段，生存者偏差重，绝对阈值不可照搬）；**年线 MA250 默认一票否决**（40 段主升浪无一例发生在年线下方）；不使用未来函数。全市场约 7 秒。
  - **表格新增两列**：**临界触发**（`n/5`，状态达标但触发为 0 会一眼可见）、**动能持续**（仅反弹动能模式有值）。
  - **无未来函数回测**（`scripts/test_snap.py` + `.workbuddy/_snap_bt.py`）：截断一致性检验证明「喂全量数据」与「截断到 asof」得到**逐字节相同**的分数；事件研究回测在 900 只长历史股票 × 60 个历史截面上评估 T+1/+2/+3/+5/+10/+20 的胜率、盈亏比与对全市场的超额。
- **🔁 9Reverse9（神奇九转 · 日 / 周 / 月多周期可叠加 · 三个筛选维度可叠加）**：两段式；周期可多选，**勾多个即叠加筛选（取并集）**。
  - **★多周期叠加的关键设计（本节重点）**：选中多个周期时，**各周期先分别独立筛选，再按股票代码取并集合并** —— 既不是取交集，也不是「先合并成一张表再统一判断」。每个周期都用**自己的一份独立参数副本**，`还差 N 个周期`、反转确认窗口、n / m 的界内阈值一律以**该周期自己的 K 线根数**计，文案单位随周期切换（日线→天、周线→周、月线→月）。这样一来，**「用日线『离九转还剩 2 日』去卡住月线九转」这类量纲错乱从结构上就不可能发生**。实测佐证：单独跑周线的候选集与「日+周+月」叠加跑出来的周线候选集**完全一致**（148 = 148）；月线单独能筛出 393 只、其中不少是日线没有的 —— 若被日线口径限制住会几乎为空。同时，周线一根 = 该自然周**最后一个交易日**的收盘（月线同理取自然月最后交易日），bar 的日期取**组内真实交易日**，不用可能落在节假日的标签日。
  - **程序一 · 三个维度并存可叠加（取并集）**：用「神奇九转」（收盘价连续 9 天低于 / 高于 4 个交易日前收盘价 → 买入 / 卖出九转）筛选，判据统一建立在**「截至参考日的买入游程长度 R」**这一个状态量上，三个维度互斥且可任意组合：
    - **① 即将到达**：R ∈ [9−N, 8]，即「还差 ≤ N 个周期」，N 可调（1~8，默认 2 → R ∈ {7,8}）。把 N 设为 **0 即关闭该维度**。
    - **② 当天达成**：R 恰为 9（信号日就是参考日当天），由「含当天达成」勾选框控制，默认关闭。
    - **③ 已达成后 x 个交易日（固定日线口径）**：R = 9 + x，**x ∈ {1,2,3} 可多选，取并集**。口径严格是「**信号日之后第 x 个交易日**（信号当天记为第 0 天，不含当天）」—— x=1 即信号次日。★ **本维度固定按日线判定**：上方的「周期（日/周/月）」选择**只影响 ①「还剩 xxx」与 ②「当天达成」**；若勾选了 ③ 而没勾日线，系统会**自动把日线加入筛选**（结果里会明确列出「日线」这一行），并且周/月线**不会**产出「已达成后 x 周」的第二种口径（避免两种单位混用）。⚠ **只认「恰好」过了 x 个交易日**：若某股已过 4 天（R=13）而只选了 x∈{1,2,3}，**不入选**；这是「已到达 x 天」的字面含义（筛一个**时间点**，不是「至少过了 x 天」）。
    - 三者**默认只开 ①**，因此**默认行为与加这个功能之前完全一致**（默认候选集不变，日线约 58 只）；想看「已过」需自行勾选 x。三个维度若被全部关闭，后端会**强制开启 ①**并在参数里披露（不静默返回空表）。
    - 数据截止日锚定在**所选范围内覆盖率 ≥80% 的最新交易日**，保证全市场计数口径一致，且要求个股当天确有行情（长期停牌不参与）。x 的单位随周期（日线=天、周线=周、月线=月），叠加时各周期的 R 各自按**自己的 bar** 算。
  - **程序二**：对这些股票拉取长历史（`hist.db` 全历史 ∪ 主库补齐最新），找出历史全部九转信号，并在信号的**对称窗口**（±5 个交易日）内定位真正开始反转的那一天 —— 买入记 `n = 真正反弹底 − 信号日`（*9Rev n天后开始真正反弹*），卖出记 `m = 信号日 − 真正顶部日`（*9Rev 提前m天开始下行*），`|n|、|m| ≤ 5`；**n / m 为负表示拐点落在信号另一侧**（买入的负 n＝信号滞后，卖出的负 m＝信号提前预警）。周 / 月线口径下窗口与单位同样换成周 / 月（*9Rev 3 周后…*、*9Rev 提前 2 月…*），**不会出现「周线说几天」**。
  - 反转须被**拐点之后**的行情确认（默认 10 根内反向 ≥3%），否则按「未确认」剔除 —— 没有这道闸，单边下跌途中每根 K 线都会被算成「地板」。
  - 陈列**两层排序**。**第 0 层（仅在同时勾选 ≥2 个维度时启用）**：先按 `当天达成 > 即将 > 已过九转` 分档，第 ③ 档内再按 x 升序（越接近信号日越靠前）；单维度时**不分档**（桶内只有一类，分档等价于不分档，加了只会平添概念）。**第 1 层（始终生效）**：① 历史买入九转的**排序分越小越靠前** → ② 一年内卖出九转信号越多越靠前。排序分 = `(Σn + K×该周期全市场均值) / (样本数 + K)`，**逐周期各算各的**（「日线的平均 n」与「月线的平均 n」量纲不同，绝不合并求均值），只统计 n ≥ 0 的样本（n &lt; 0 属信号滞后，单列展示），并按样本量向该周期全市场均值收缩 —— 实测首版 Top-1 只靠 **1 个** n=0 样本就以平均 n=0 霸榜（413 只候选里 21 只样本数 ≤ 1），与「历史上**每次**」的语义不符；收缩后 Top-10 再无单样本股（K=0 时是 5 只）。K 可在高级参数里调，设 0 即退回纯平均 n 的字面口径。**叠加时**顶层排序分取各命中周期的**最小值**（即「该股在哪个周期上最强」），维度档同样取各周期的**最优（最小）档**，第 2 依据「一年内卖出九转」取各周期**求和**（计数无量纲、可加）。折叠态只露**代码 + 名称 + 周期徽章 + 维度徽章 + 右置「展开」**，展开后**按周期分组**分列买入 / 卖出九转的「信号日 / 真正反转日 / n或m / 信号收盘 / 阶段极值 / 记录」，***③ 维度额外给出九转信号日与信号日收盘***，每组表头自带自己的单位；多周期卡片顶部有提示条，**不同周期的 n / m 不合并计算**。明细**按需懒渲染**（几百只也不卡），支持一键全部展开与 CSV 导出（含明细段、命中维度列、排序档位列）。
  - 附实测口径：卖出九转约 **55%** 的真顶落在信号**之后** —— 它更像「提前预警」而不是滞后的见顶确认；买入九转约 **26%** 的真底落在信号之前。耗时：日线全市场约 6~10 秒，单独跑周线约 17 秒、月线约 11 秒，**三周期叠加约 27 秒**。
- **🎯 Bet on（长期布局）**：找**可能持续一年以上**的上涨行情，并回答三件事 —— **① 现在能不能买**（买点档 + 0~100 买入评分）、**② 这段行情大概还能走多久**（按该股**自己**的历史周期推算，单位自动切 周 / 月 / 年）、**③ 什么时候卖**（具体到这只股票的目标价区间与四条量化纪律线）。折叠态只露一行摘要，右置**「详细 ▾」**展开 9 个小节：得分构成（7 项权重 + 折扣明细）、入选理由（每条带实测数字）、历史周期档案（该股自己的上涨段明细表）、所在行业、**上游商品期货联动**（按行业映射品种并给产业因果方向：同向利好 / 成本反向）、基本面与估值快照、建议卖出的量化指标、提醒与风险、长期走势图（月线 + 历史上涨段高亮，按需加载）。全市场约 15 秒。
  - **买点三档**（对应用户「启动前埋伏 / 山腰参与」的诉求）：**T2 山腰确认**（主推，收盘站上 MA250 且 MA250 上行）、**T3 加速/已走远**（距 250 日低点已翻倍，只宜加仓不宜建仓）、**T1 启动前埋伏**（左侧，低置信）、**T4 观察**。每个档位都标注了研究实测的 120 日胜率。
  - **「预估周期至少」过滤器**：直接服务「持续一年以上」这个诉求 —— 可选 不限 / 3 个月 / 6 个月 / **1 年** / 2 年，按该股**自身历史节奏**推出的中位周期时长过滤；样本不足、算不出时长的股票会被排除（不做默认放行）。实测三个行业板块选「至少 1 年」时从 310 只收敛到 21 只（剔除 289 只）。
  - **方法论与诚实边界（重要）**：素材是两份长周期研究档案（《长周期上涨股票量化识别手册》+《run2 买入侧信号研究结论》）与两轮独立复核，**两轮研究的最终结论都是 `RESEARCH_REJECTED`** —— run1 的 Deflated Sharpe 仅 0.8107（< 0.95）、Haircut 后夏普从 1.25 腰斩到 0.64；run2 的「提前埋伏」净增量只有 +1.49pp、8 年里 4 年为负；横截面复核还发现位置类因子对未来 120 日收益是**负向**（反转）。因此本模块**不假装能预测**，只做三件有据可依的事：用研究里**唯一在任何口径下都没被否掉**的「状态基线」当主锚（STATE_ABOVE 实测 120 日胜率 67.94%、最大不利偏移仅 −10.69%）；用该股**自身历史**的上涨段分布给出周期与目标价的量级参考；给出可执行的卖出纪律。被证伪的「埋伏」档保留但明确标注低置信度，目标价在样本 <3 段时**直接不给**（宁缺勿假）。
  - **双轨制：主榜（严格）+ 观察榜（宽松），两榜严格分离**（2026-09-23 新增）。既然封段回测实测主榜分数对未来收益的 Spearman IC ≈ 0，就不该假装它能预测 —— 所以输出两条**互不混排**的轨：
    - **主榜**（即上方那套）：7 项加权打分 + 5 类乘法折扣 + 分数门槛（默认 60）。定位是**「可辩护的筛选漏斗 + 卖出纪律工具」**，不承诺预测力。
    - **观察榜「🔍 长期形态观察榜」**：**不设分数门槛、不做显著性检验**，只用三条长期形态的必要条件把形态像的股票捞出来（① 长期趋势未破：站上年线，或距年线 ≤8% 且年线不再下行；② 中期结构已建立：MA20>MA60>MA120 近 60 日占比 ≥35%；③ 不在死水区：250 日区间位置 ≥0.15），并要求至少 500 根日K。界面带**显著警示条**，明写「⚠ 宽松轨 · **不是推荐**」与 IC ≈ 0 的实测数字；观察榜会剔除主榜已入选的股票，**绝不与主榜混合排序**。CSV 导出含观察榜独立分段。
    - 为什么要有观察榜：用户明确要求「封段回测时能筛出指定的样本股」。实测在「段前 + 段内」的 10 个样本时点上，主榜命中 4 个、**观察榜命中 7 个**（段内山腰位 11/11 全中）。代价是观察榜对「段内峰值日」也是 11/11 全中 —— **它分不清山腰和顶部**，这正是它只能叫「观察榜」的原因。
  - **封段回测与实测结论（诚实披露）**：内置 `scripts/test_beton_backtest.py`，把长历史截断到历史时点、用与线上**完全相同**的分析函数重跑（不引入未来函数），时点分四类：段前 60 日 / 段内 55% / **段内峰值日（真·追顶，反向对照）** / 段末后 20 日。**505 个随机截断时点**实测 Spearman IC：未来 120 日 **−0.002**、未来 250 日 **−0.018**；头部（≥72.6 分）未来 250 日 +34.9% 反而略**低于**尾部（≤48.5 分）的 +38.7%；真顶误伤率 57%、大机会捕获率 50%。这与 run1 / run2 的 `RESEARCH_REJECTED` 完全一致。另需点名：**主榜给某些样本点低分是「程序正确」而非 bug** —— 000408 在 2021-05-19 已涨 333.8% 且区间位置 1.00（贴着前高）得 53.2 分、300750 在 2020-12-09 已涨 204.7%、位置 0.95 得 56.6 分，按研究 §6.5 的半山腰→后段分界（收盘分位 ≈0.874）这两点**已在「后段」**，强行抬高就等于把追顶当买点。
  - **数据与口径**：长历史来自 `data/hist.db`（1990 起、中位 3300 根，**前复权**）并与主库 `daily` 合并。关于复权口径的实测澄清：曾一度以为 hist.db 是「不复权」，实测推翻 —— 000408 全历史 6826 根中单日跌幅超过 15% 的次数为 **0**、600519 起点 **4.00 元**、002371 最新 634 元，均证明序列**本身就是前复权**（与通行做法一致）。因此用于兜底的 `_repair_actions()`（按「跌幅超板块涨跌停上限 +3pp」且「开盘/前收 ≤0.97」识别送股跳空）在正常数据上返回 0 事件是**正确行为**，不是失灵；**数据本身未做任何加工**。打分因子全部**只用 t 时刻及之前的收盘数据**；历史周期用 v4 趋势状态机（MA60/MA120 死叉需**连续 10 日**确认、深回撤终止线 45%，两者均可在高级参数里调）切段，它必须用到「这段后来如何收场」的信息，因此是**标签而非信号**，只用于统计历史体质与周期时长，**不参与打分** —— 这一点在界面里也明写。仅主库 ~288 根日K 的股票（约 1200 只，多为 301/688/北交所新代码）因不足 500 根被跳过。
  - **价格区间的口径修正**：默认区间由 `3~500 元` 放宽为 **`2~3000 元`**。这不是为了迁就样本股，而是原上限 500 元会**把高价优质股整片误杀**（002371 北方华创 672.92 元、600519 贵州茅台 1275.16 元都被「价格区间」跳过），已明显偏离常识；下限取 2 元是 A 股「面值退市」关注线的通行代理。修正后全市场因「价格区间」被跳过的仅 57 只。
  - **基本面只到 PE / PB / 股息这一层**（本地库有 valuation / snapshot / dividend，**没有营收/利润/ROE 等财务报表数据**），行业前景只用「行业动量 + 上游商品期货」两个侧面近似，其余必须自行核实 —— 这一点在「详细」面板里也明写。
- **蚂蚁呀欸**：四层流水线（硬过滤 → 形态 → 打分 → 启动标记），阈值全部可调
- **持有个1000年试试呢？**（蚂蚁呀欸 · 超长周期版）：同源多因子筛选，窗口拉长到 **10 / 20 / 25 / 30 年**，从宏观视角筛「周期波动明显 + 周期存在时间长」的股票 —— 用 ZigZag 识别**深蹲（≥35%）+ 翻倍反弹（≥70%）**的完整循环，7 项得分（循环 / 双向波动 / 均值回复 / 长存 / 长期超额 / 熊市韧性 / 周期低位）按窗口缩放评定；未上市满窗口的股票从上市日起分析（最少 5 年）。自带全历史数据缓存（`data/hist.db`，新浪源一次拉取永久复用），点击结果代码可看**长周期月线图**（对数轴 + 循环顶底标注 + 上证指数对比）
- **相似股**：a 几乎一致 / b 走势相反 / c 时移相似，对比图每类只画最像的 2 只（目标股鲜红、A蓝/B橙/C绿），点击图表可在新窗口打开 2x 高清大图（大周期/K线图同样支持）
- **行情查看（K 线工作站）**：单只股票 / 指数 K 线（MA5/10/20/60 自动绘制，图例可点开关）。支持**鼠标滚轮缩放（以光标位置为锚点，不会跳飞）**、**按住拖拽平移**、**双击复位**、**十字光标 + 当根数据浮框**（开/高/低/收/量/额）、**成交量副图**、**导出图片**。指标可选 **BOLL 布林线**（20 日 ±2σ，默认关闭，点图例 BOLL 开启；中轨 = MA20 虚线、上下轨带蓝色填充带，悬停浮框显示上/中/下三值）。指数可直接输入 `sh000300`（沪深300）等带 `sh`/`sz` 前缀的代码，自动识别并标注「指数」徽章；个股查不到时回落指数表。空态自带 4 个可点击示例（600519 / 000001 / 300750 / sh000300）。点击任意结果表的代码一键跳到本页，点击股票名称跳同花顺外链。
- **外观调整（5 套主题）**：顶栏 **🎨 外观** 按钮弹出面板，**暗色（罗德岛终端）/ 亮色（羊皮纸）/ 粉色（樱花）/ 蓝色（静谧）/ 米色（燕麦）** 点击即切换并记忆偏好（localStorage）。每套主题都定义了完整色板（含 K 线专用 `--k-*` 变量：涨跌色、网格、均线、成交量、布林线），切换主题后所有图表（K 线 / 相似股 / 大周期 / 长周期）自动重绘，不会出现「白底白线」。首次渲染前由 head 内联脚本预置主题，避免闪白。
- **前瞻预警**：日历事件 + 异动侦测 + 冷门板块 + **国家队资金**（ETF/汇金/社保/证金四列表，最新报告期前十大股东口径，可独立开关、折叠展示）+ 外资重仓 + 拥挤度监控 + **产业链传导** + **宏观雷达**（新闻主题扫描，无回波不显示）—— 两者是**各自独立**的模块与开关（点击任一卡片标题「选入/踢出」互不影响，导出报告里也是两张独立卡片）+ 核心信号合成，可导出独立网页报告
- **大周期**：月 K 线 + 回归通道 + **六因子趋势引擎**（RSL / 均线排列 / Weinstein 阶段 / 月线 MACD / ROC 动量 / 通道位置加权合成，评分制）+ 走势虚线外推（1~14 年）
- **快讯轮播**：顶部横向滚动财经快讯；常驻 CCI 市场情绪（多空判断 + 预警标红）、伦敦金/布伦特原油（轮替播放、行情专页跳转）、期货异动预警（主连涨跌幅≥5%）；关键词智能跳转（上市公司名跳个股页 / 指数词与机构观点跳检索）；右端 ⟳ 按钮可跳过缓存强制刷新字幕
- **分红时点预测**（顶栏 🗓 按钮）：从本地分红历史给每只股票建立「除权习惯画像」（年报季/中期/季度/不规则），据此**每周只对可能除权的几百只**查分红，把同步请求量从全市场 5500+ 收敛到约 1/5（旺季覆盖约 71%）。内置四条规则：a 近几年持续亏损不读；b 上市来从未分红不读；c 本习惯周期内已分红不读；d 每年 2 月底全市场增量一次（每年仅一次）。面板可查看任一周的候选清单与规则命中数
- **GIF 悬浮窗**：右下角动图窗（32 张），点击切换下一张，可拖动（可收起/恢复）
- **🎓 仅供学习**（B站指定 UP主 内容挖掘）：只读取你保存的 **UP主本人发布** 的视频 / 动态 / 字幕 / 评论（**不含他人搬运、转载、二次分析**），提取其中出现具体股票（代码或简称）的内容并保留原文片段，按权重排序。UP主 自己内容为高权重、他人评论为低权重。
  - **安全策略**：用 `curl_cffi` 复刻真实 Chrome TLS 指纹规避风控，全程**串行 + 最小间隔限速（默认 4.5s）+ 单轮请求硬闸**，不并发、不自动登录、不读取会员/充电专属内容。
  - **本地视频文稿**（可选）：匿名拿不到视频字幕时，可下载音频到本机后用**免费离线引擎**（faster-whisper 或 funasr SenseVoice）转写为文稿，补全视频正文的股票提及。音频与文稿**只存本机**（`data/bili_video/`、`data/bili_asr/`），**不上传任何服务器**；两个引擎装其一即可，都不装则该功能自动降级隐藏。安装：`pip install faster-whisper`（推荐）或 `pip install funasr modelscope`。
  - **本地存档 / 增量抓取**：抓过的 视频/动态/评论 提及以**简略文本**长期存本机 `data/bili_archive/`（每个 UP主 一份，含各自的覆盖区间）。再次抓同一 UP主 时，本地已覆盖的时间段**直接复用、不再联网**，只增量抓「未覆盖的尾部」；边界那天会重拉一次并用 id 去重（重复内容自动跳过）。**多个 UP主 各自独立**、按实际覆盖情况取策略（全量 / 增量 / 纯本地 0 网络）。面板可查看各 UP主 覆盖区间并单独/整体清空；也可临时关闭「优先本地存档」开关做全量重抓。
  - **UP主 自定义名称**（可选，针对已保存条目）：昵称有时读不出来（会显示成 `UIDxxxx`）。保存后点已保存列表里名称旁的 **✎** 给它起名；自定义名**优先显示**，留空则恢复自动昵称。每个 UP主 独立，随时可改。
  - **加载界面「后台运行」**：筛选 / 抓取等长任务的加载窗口上有 **⤵ 后台运行** 按钮，点击即收起窗口、任务照常在后台执行（不会中断），右下角出现状态角标——运行中可点角标**恢复进度窗口**，完成后提示「已完成，结果已显示」。有后台任务时不会再叠加第二个长任务（防止进度互踩），点「取消任务」则照常中止。

所有模块都支持先选股票范围（全部 / 沪 / 深 / 北），再选板块，再跑筛选。范围与板块**随时可改**。

## 启动

### 方式 A：一键启动（Windows，推荐）

双击 `start.bat` 即可。脚本会自动寻找一个**已装好依赖**的 Python
（依次尝试 PATH 的 `python` → `py -3` → 常见安装路径），全部不可用时
自动执行 `pip install -r requirements.txt` 后再启动，无需手动预装。

> ⚠️ 请务必通过 `start.bat`（或方式 B）启动后访问
> <http://127.0.0.1:8765/> —— 直接双击 `index.html` 打开（file:// 协议）
> 时浏览器会拦截全部数据接口，页面会显示红色提示条，功能不可用。

### 方式 B：手动启动（任意系统）

```bat
pip install -r requirements.txt
python -m uvicorn app.main:app --host 127.0.0.1 --port 8765
```

然后浏览器打开 <http://127.0.0.1:8765/>。

## 数据

> ⚠️ **关于数据库与 Git：** `data/unified_data.db` 约 1.3GB，**超过 GitHub 单文件 100MB 上限**，因此已被 `.gitignore` 排除，克隆仓库后默认**不含数据库**。请按下方方式之一获取后放入 `data/` 即可。如果你是直接拿到本文件夹（非 git 克隆），则 db 已随附，开箱即用。

**方式一（推荐，最快）：下载预构建数据库**
从本项目的 GitHub Release 页面（或作者提供的网盘链接）下载 `unified_data.db`，放入 `data/` 目录。
当前预构建库约 5554 只 · 150 万条日线 + 估值/分红，开箱即用。

**方式二：从零同步**
删除 `data/unified_data.db*` 后重启程序，按网页引导三步：

1. 点 **「刷新信息」** —— 拉取全市场股票列表与板块映射（约 1 分钟）
2. 点 **「同步数据」** —— 按所选范围拉取日线 / 估值 / 分红（沪深京全部约 30 分钟，可先选小范围）
3. 同步完成后**快照表自动后台构建**

此后在网页右上角点 **「⬇ 同步数据」** 即可**增量补齐**最新行情（只拉各股最新日期之后的部分，几分钟内完成）。

若需要从零重建（如发布精简版）：删除 `data/` 下的 `unified_data.db*` 后重启程序，按引导三步：

1. 网页右上角点 **「刷新信息」** —— 拉取全市场股票列表与板块映射（约 1 分钟）
2. 点 **「同步数据」** —— 按所选范围拉取日线 / 估值 / 分红（沪深京全部约 30 分钟，可先选小范围）
3. 同步完成后**快照表自动后台构建**（估值/股息条件依赖），也可手动触发

数据留存于本地 `data/unified_data.db`，重启程序不丢失；「⬇ 同步数据」永远只拉增量。

**⏹ 停止同步（即时生效）**：同步进行中，顶栏按钮会变成「⏹ 停止同步」，点击后按钮先进入「⏳ 正在停止…」过渡态，后端**在 0.25s 内**感知并中断：主循环改为 0.25s 轮询取消信号（旧实现用 `as_completed` 阻塞，要等一个拉取任务超时结束，最长约 45s）；未开始的股票任务被整体取消；正在跑的少数请求会在下一次检查点（≤0.2s）自行退出；准备阶段（分红/估值批量预取）与「分红降级链」也都布了检查点。实测停止延迟：准备阶段 0.8s、分红阶段 1.4s、逐股同步阶段 **0.08s**（端到端 API 实测 1.75s / 0.23s）。已写入的数据用 `INSERT OR REPLACE`，中途停止不会破坏数据；下次点「同步数据」会从断点继续。

数据源：

- AKShare（主）
- 新浪 / 腾讯 / 东财 / 百度（兜底）

**注意**：同步需要联网。`scripts/import_data.py` 为可选脚本（从旧版 `stock_data.db` 迁移存量数据，用法 `python scripts/import_data.py 源库路径`），新用户无需使用。

## 性能设计

- **快照表 `snapshot`**：每只股票的最新行情 / PE-TTM / PB / PE 分位 / PB 分位 / 股息率预计算成一张小表。PE/PB 低估、高股息率条件直接查快照（毫秒级），同步数据后自动刷新，无需每次扫描全量估值。
- **常驻进程池**：形态打分、蚂蚁扫描是纯 CPU 计算，受 Python GIL 限制，用的是 `ProcessPoolExecutor` 多进程并行；进程池常驻复用（`app/core/pool.py`）
- **索引优化**：`valuation` 表额外建 `date` 索引
- **按需加载**：条件筛选按条件所需字段加载（技术条件只查日线、估值条件只查快照），串行 + 缓存共享（多线程在 GIL 下反而更慢）

## 设计要点

- **统一表结构**：所有模块共用 `daily` / `valuation` / `meta` / `snapshot` 等主表
- **按需取数**：每个模块只查必要的列与时间窗，单股单次查询 < 5ms
- **每线程独立 SQLite 只读连接**，全局一个写连接；WAL 模式支持读写并发
- **范围+板块 = 一处定义，五处复用**（5 个筛选模块共用同一份范围过滤）
- **前端零构建**：纯 HTML + CSS + JS，刷新即生效
